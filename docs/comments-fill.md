## 2.8 Excel에서 붙여넣기

Excel에서 복사한 이름(과 설명) 열을 코멘트 그리드에 한 번에 넣는다. **넣는 것은 그리드 값뿐이다. `저장`을 눌러야 DB에 반영된다.**

### 기본 순서

1. Excel에서 넣을 범위를 고르고 복사한다(`Ctrl+C`, macOS는 `Cmd+C`).
2. SchemaForge 그리드에서 **넣기 시작할 행의 칸**을 한 번 클릭해 고른다. 입력 상태로 들어가지 않는다.
3. `Ctrl+V`(macOS는 `Cmd+V`)를 누르거나, 오른쪽 클릭 > `붙여넣기`.
4. 값이 들어간 행에 `변경` 체크가 생기고, 상태줄에 `N개 행에 붙여넣었습니다. 저장해야 DB에 반영됩니다.`가 뜬다.
5. 확인한 뒤 `저장`을 누른다. 잘못 들어간 행은 [행 되돌리기](comments-save.md#27-행-되돌리기)로 되돌린다.

### 예: 두 열(이름·설명)을 붙여넣기

Excel에 이렇게 있다.

| | A | B |
|---|---|---|
| 1 | 주문번호 | 주문을 구분하는 번호 |
| 2 | 주문일자 | |
| 3 | 고객번호 | 주문한 고객 |

A1:B3을 복사하고, 테이블 문서 컬럼 탭에서 `ORDER_NO` 행의 `이름` 칸을 고른 뒤 `Ctrl+V`(macOS `Cmd+V`)를 누르면 이렇게 된다.

| 그리드 행 | 이름 | 설명 |
|---|---|---|
| `ORDER_NO` (고른 행) | 주문번호 | 주문을 구분하는 번호 |
| 바로 아래 행 | 주문일자 | (원래 값 그대로) |
| 그 아래 행 | 고객번호 | 주문한 고객 |

상태줄: `3개 행에 붙여넣었습니다. 저장해야 DB에 반영됩니다. 빈 칸 1개는 넣지 않았습니다.`

같은 범위를 `설명` 칸을 고른 채 붙여넣으면 A열이 설명에 들어가고 B열은 버려진다. 설명만 넣으려면 Excel에서 설명 열만 복사해 `설명` 칸에 붙여넣는다.

### 넣는 규칙

| 상황 | 동작 |
|---|---|
| 시작 행 | 고른 행부터 아래로 한 줄씩 넣는다. 여러 행을 골랐으면 화면에서 가장 위의 행부터 |
| 행 순서 | **화면에 보이는 순서**를 따른다. 검색·`미작성만`·`변경만`으로 숨은 행은 건너뛴다 |
| 고른 칸이 `설명`이 아님(이름·컬럼명·타입 등) | 첫 칸은 이름, 둘째 칸은 설명에 넣는다. 셋째 칸부터는 넣지 않고 `셋째 칸부터는 넣지 않았습니다.`로 알린다 |
| 고른 칸이 `설명` | 첫 칸을 설명에 넣는다. 이름은 건드리지 않는다. 둘째 칸부터는 넣지 않고 `둘째 칸부터는 넣지 않았습니다.`로 알린다 |
| 빈 셀 | 넣지 않는다. 있던 값을 지우지 않는다. 지우려면 셀에서 직접 지운다 |
| 아래 행이 모자람 | 들어가는 만큼만 넣고 `N줄 중 M줄만 넣었습니다(아래 행이 모자랍니다).`로 알린다 |
| 셀 하나를 복사하고 행을 여럿 골랐음 | 고른 행 모두에 그 값을 넣는다(Excel과 같다) |
| 셀 안에 줄바꿈·탭이 든 셀 | Excel이 따옴표로 감싸 복사한 셀은 한 칸으로 넣는다. 여러 행으로 흩어지지 않는다 |
| 이름에 `§`가 든 줄 | 그 줄은 넣지 않고 `N줄 건너뜀 - 이름에 § 포함(…)`으로 알린다 |
| 이름+설명이 7,500바이트를 넘는 줄 | 그 줄은 넣지 않고 `N줄 건너뜀 - 길이 한도 초과(…)`로 알린다 |

- 고른 행이 없으면 `붙여넣을 행을 먼저 고르세요.`, 클립보드에 글자가 없으면 `클립보드에 붙여넣을 글자가 없습니다.`가 보인다.
- **셀을 입력하는 중의 `Ctrl+V`(macOS는 `Cmd+V`)는 그 칸에 글자를 넣는다.** 여러 행에 넣으려면 먼저 입력을 끝내고 칸만 고른 상태에서 누른다.
- 개체 문서 머리글의 이름·설명 입력칸은 그리드가 아니라 보통 입력칸처럼 붙여넣는다.
- 붙여넣은 뒤 목록을 다시 거르지 않는다. `미작성만`이나 `변경만`을 켠 채 붙여넣어도 그 행이 바로 사라지지 않는다.

## 2.9 이름 제안으로 채우기

빈 컬럼을 채울 때 다른 테이블의 같은 컬럼명이 이미 쓰는 이름(`CUST_NO` = `고객번호`)을 제안해, 같은 이름을 다시 치지 않게 한다.
테이블·뷰 문서의 컬럼 탭, 프로시저·함수 문서의 파라미터 그리드, 테이블 타입 문서의 컬럼 그리드, 테이블 문서의 `인덱스`·`제약조건` 탭에서 된다.

1. 제안이 있는 빈 행이 보이면 그리드 위에 `빈 이름 N개에 이름 제안이 있습니다.`와 `제안으로 채우기` 버튼이 나온다.
2. `제안으로 채우기`를 누르면 **보이는 행 중 이름이 빈 행에만** 제안이 들어간다. 검색·필터로 숨은 행은 바꾸지 않는다.
3. 들어간 행은 `변경`으로 표시된다. `변경만`을 켜서 확인하고, 아니다 싶은 행은 [되돌린다](comments-save.md#27-행-되돌리기).
4. `저장`을 눌러야 DB에 반영된다.

어떤 값을 제안하나:

- 그 DB의 다른 테이블에서 이름이 같은 컬럼에 **가장 많이 쓰인 이름**이다. 같은 수면 가나다순으로 앞의 것이다. 뷰 컬럼과 이 개체 자신의 컬럼은 세지 않는다.
- **뷰 문서는 뷰 컬럼마다 실제로 가져오는 원본 테이블 컬럼을 찾아 그 이름을 먼저 제안한다.** 이름을 바꾼 컬럼(`o.Id AS OrderId`)도 원본을 따라간다.
  원본이 없거나(식으로 만든 컬럼) 원본에 이름이 없으면 같은 컬럼명 제안을 쓴다.
- **프로시저·함수의 파라미터는 앞의 `@`를 뺀 이름으로 맞춘다**(`@CUST_NO` ↔ `CUST_NO`). 맞는 테이블 컬럼이 없으면 다른 프로시저·함수의
  같은 파라미터명에 가장 많이 쓰인 이름을 제안한다.
- **테이블 컬럼은 외래키가 가리키는 컬럼의 이름을 먼저 제안한다.** 외래키가 없거나 가리키는 컬럼에 이름이 없으면 같은 컬럼명 제안을 쓴다.
- **테이블 타입의 컬럼도** 같은 컬럼명의 이름을 제안한다.
- **인덱스·제약조건 탭은 키 컬럼의 이름으로 지은 이름을 제안한다**(`주문일자 인덱스`, `고객 참조` 등). FK는 참조 테이블, DEFAULT는 대상 컬럼의 이름을 쓴다.
- 설명은 제안하지 않는다.
- 제안은 문서를 열 때 한 번 읽는다. 다른 문서에서 저장한 이름은 `새로고침`해야 제안에 반영된다.
