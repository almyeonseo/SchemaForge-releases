## 2.8 Excel에서 붙여넣기

Excel에서 복사한 이름(과 설명) 열을 코멘트 그리드에 한 번에 넣는다. **넣는 것은 그리드 값뿐이다. `저장`을 눌러야 DB에 반영된다.**

### 기본 순서

1. Excel에서 넣을 범위를 고르고 복사한다(`Ctrl+C`, macOS는 `Cmd+C`).
2. SchemaForge 그리드에서 **넣기 시작할 행의 칸**을 한 번 클릭해 고른다. 입력 상태로 들어가지 않는다.
3. `Ctrl+V`(macOS는 `Cmd+V`)를 누르거나, 오른쪽 클릭 > `붙여넣기`.
4. 값이 들어간 행에 `변경` 체크가 생기고, 상태줄에 `N개 행에 붙여넣었습니다. 저장해야 DB에 반영됩니다.`가 뜬다.
5. 확인한 뒤 `저장`을 누른다. 잘못 들어간 행은 [행 되돌리기](comments.md#27-행-되돌리기)로 되돌린다.

### 예: 두 열(이름·설명)을 붙여넣기

Excel에 이렇게 있다.

| | A | B |
|---|---|---|
| 1 | 주문번호 | 주문을 구분하는 번호 |
| 2 | 주문일자 | |
| 3 | 고객번호 | 주문한 고객 |

A1:B3을 복사하고, 테이블 문서 컬럼 탭에서 `ORDER_NO` 행의 `이름` 칸을 고른 뒤 `Ctrl+V`(macOS `Cmd+V`)를 누르면 이렇게 된다.

| 그리드 행 | 이름 | 설명 |
|---|---|---|
| `ORDER_NO` (고른 행) | 주문번호 | 주문을 구분하는 번호 |
| 바로 아래 행 | 주문일자 | (원래 값 그대로) |
| 그 아래 행 | 고객번호 | 주문한 고객 |

상태줄: `3개 행에 붙여넣었습니다. 저장해야 DB에 반영됩니다. 빈 칸 1개는 넣지 않았습니다.`

같은 범위를 `설명` 칸을 고른 채 붙여넣으면 A열이 설명에 들어가고 B열은 버려진다. 설명만 넣으려면 Excel에서 설명 열만 복사해 `설명` 칸에 붙여넣는다.

### 넣는 규칙

| 상황 | 동작 |
|---|---|
| 시작 행 | 고른 행부터 아래로 한 줄씩 넣는다. 여러 행을 골랐으면 화면에서 가장 위의 행부터 |
| 행 순서 | **화면에 보이는 순서**를 따른다. 검색·`미작성만`·`변경만`으로 숨은 행은 건너뛴다 |
| 고른 칸이 `설명`이 아님(이름·컬럼명·타입 등) | 첫 칸은 이름, 둘째 칸은 설명에 넣는다. 셋째 칸부터는 넣지 않고 `셋째 칸부터는 넣지 않았습니다.`로 알린다 |
| 고른 칸이 `설명` | 첫 칸을 설명에 넣는다. 이름은 건드리지 않는다. 둘째 칸부터는 넣지 않고 `둘째 칸부터는 넣지 않았습니다.`로 알린다 |
| 빈 셀 | 넣지 않는다. 있던 값을 지우지 않는다. 지우려면 셀에서 직접 지운다 |
| 아래 행이 모자람 | 들어가는 만큼만 넣고 `N줄 중 M줄만 넣었습니다(아래 행이 모자랍니다).`로 알린다 |
| 셀 하나를 복사하고 행을 여럿 골랐음 | 고른 행 모두에 그 값을 넣는다(Excel과 같다) |
| 셀 안에 줄바꿈·탭이 든 셀 | Excel이 따옴표로 감싸 복사한 셀은 한 칸으로 넣는다. 여러 행으로 흩어지지 않는다 |
| 이름에 `§`가 든 줄 | 그 줄은 넣지 않고 `N줄 건너뜀 - 이름에 § 포함(…)`으로 알린다 |
| 이름+설명이 7,500바이트를 넘는 줄 | 그 줄은 넣지 않고 `N줄 건너뜀 - 길이 한도 초과(…)`로 알린다 |

- 고른 행이 없으면 `붙여넣을 행을 먼저 고르세요.`, 클립보드에 글자가 없으면 `클립보드에 붙여넣을 글자가 없습니다.`가 보인다.
- **셀을 입력하는 중의 `Ctrl+V`(macOS는 `Cmd+V`)는 그 칸에 글자를 넣는다.** 여러 행에 넣으려면 먼저 입력을 끝내고 칸만 고른 상태에서 누른다.
- 개체 문서 머리글의 이름·설명 입력칸은 그리드가 아니라 보통 입력칸처럼 붙여넣는다.
- 붙여넣은 뒤 목록을 다시 거르지 않는다. `미작성만`이나 `변경만`을 켠 채 붙여넣어도 그 행이 바로 사라지지 않는다.

## 2.9 이름 제안으로 채우기

빈 컬럼을 채울 때 다른 테이블의 같은 컬럼명이 이미 쓰는 이름(`CUST_NO` = `고객번호`)을 제안해, 같은 이름을 다시 치지 않게 한다.
테이블·뷰 문서의 컬럼 탭, 프로시저·함수 문서의 파라미터 그리드, 테이블 타입 문서의 컬럼 그리드, 테이블 문서의 `인덱스`·`제약조건` 탭에서 된다.

1. 제안이 있는 빈 행이 보이면 그리드 위에 `빈 이름 N개에 이름 제안이 있습니다.`와 `제안으로 채우기` 버튼이 나온다.
2. `제안으로 채우기`를 누르면 **보이는 행 중 이름이 빈 행에만** 제안이 들어간다. 검색·필터로 숨은 행은 바꾸지 않는다.
3. 들어간 행은 `변경`으로 표시된다. `변경만`을 켜서 확인하고, 아니다 싶은 행은 [되돌린다](comments.md#27-행-되돌리기).
4. `저장`을 눌러야 DB에 반영된다.

어떤 값을 제안하나:

- 그 DB의 다른 테이블에서 이름이 같은 컬럼에 **가장 많이 쓰인 이름**이다. 같은 수면 가나다순으로 앞의 것이다. 뷰 컬럼과 이 개체 자신의 컬럼은 세지 않는다.
- **뷰 문서는 뷰 컬럼마다 실제로 가져오는 원본 테이블 컬럼을 찾아 그 이름을 먼저 제안한다.** 이름을 바꾼 컬럼(`o.Id AS OrderId`)도 원본을 따라간다.
  원본이 없거나(식으로 만든 컬럼) 원본에 이름이 없으면 같은 컬럼명 제안을 쓴다.
- **프로시저·함수의 파라미터는 앞의 `@`를 뺀 이름으로 맞춘다**(`@CUST_NO` ↔ `CUST_NO`). 맞는 테이블 컬럼이 없으면 다른 프로시저·함수의
  같은 파라미터명에 가장 많이 쓰인 이름을 제안한다.
- **테이블 컬럼은 외래키가 가리키는 컬럼의 이름을 먼저 제안한다.** 외래키가 없거나 가리키는 컬럼에 이름이 없으면 같은 컬럼명 제안을 쓴다.
- **테이블 타입의 컬럼도** 같은 컬럼명의 이름을 제안한다.
- **인덱스·제약조건 탭은 키 컬럼의 이름으로 지은 이름을 제안한다**(`주문일자 인덱스`, `고객 참조` 등). FK는 참조 테이블, DEFAULT는 대상 컬럼의 이름을 쓴다.
- 설명은 제안하지 않는다.
- 제안은 문서를 열 때 한 번 읽는다. 다른 문서에서 저장한 이름은 `새로고침`해야 제안에 반영된다.

## 2.10 같은 컬럼명 이름 맞추기

`REG_DT`·`CUST_NO`처럼 여러 테이블에 되풀이되는 컬럼의 이름을 한 화면에서 맞춘다. 테이블 문서를 하나씩 열지 않아도 된다.

### 여는 법

1. DB 탐색기 검색에서 찾을 대상을 `컬럼`으로 바꾸고 컬럼명을 찾는다(검색 쓰는 법은 [1장](getting-started.md)).
2. 결과 목록의 줄을 오른쪽 클릭 > `이 컬럼명의 이름 맞추기 (CUST_NO)`.
3. 그 DB에서 이름이 같은 컬럼을 모은 문서가 열린다. 탭 제목은 컬럼 이름(`CUST_NO`)이다.

- 이름이 **정확히 같은**(대소문자 무시) **테이블 컬럼과 뷰 컬럼**을 모두 읽는다. `CUST_NO_OLD` 같은 부분 일치는 넣지 않는다. 테이블 타입 컬럼은 넣지 않는다.
- 같은 이름으로 다시 열면 새로 읽지 않고 열려 있는 탭으로 간다.
- 상태줄에 `'CUST_NO' 컬럼 20개 로드 완료 (테이블 18개, 뷰 2개)`처럼 보인다.

### 화면

![같은 컬럼명 문서 — UserId의 이름이 둘로 갈린 상태에서 한 행을 맞춘 모습](../images/column-name-document.png)

- 그리드 칸: `변경 · 스키마 · 개체 · 종류 · 이름 · 타입 · 설명`. `종류`가 `테이블`/`뷰`를 가른다.
- **쓰인 이름** 줄: 지금 그리드에 쓰인 이름을 많이 쓴 순으로 개수와 함께 보이고, 이름이 빈 행은 `미작성 N개`로 따로 적는다. 값을 고치면 개수가 곧바로 바뀐다.
- `넣을 이름` · `넣을 설명(비우면 그대로)` 칸과 `고른 행에 적용` · `보이는 행 모두에 적용` 버튼. 두 칸 중 값을 넣은 칸만 바꾼다.
- 툴바의 저장·내보내기·가져오기·`미작성만`·`변경만`과 행 되돌리기·붙여넣기는 다른 코멘트 문서와 같다.
- **검색어는 컬럼명 대신 개체(테이블·뷰)의 개체명과 이름·설명을 본다**(검색 칸 안내는 `개체명·이름·설명 검색`). 컬럼명은 모두 같아서다.

### 이름 맞추는 순서

1. **쓰인 이름**에서 맞출 값(예: `고객번호 12`)을 누른다. 아래 `넣을 이름` 칸에 그 값이 들어간다. 직접 입력해도 된다.
2. 바꿀 범위를 정한다.
   - 몇 행만 바꾸려면 그리드에서 그 행들을 고르고 `고른 행에 적용`.
   - 보이는 행 전부를 바꾸려면 `보이는 행 모두에 적용`. 검색이나 `미작성만`으로 좁혀 두었으면 **보이는 행만** 바뀐다. 숨은 행은 바뀌지 않는다.
3. 상태줄에 `N개 행에 '고객번호'을(를) 넣었습니다. 저장해야 DB에 반영됩니다.`가 뜬다. 이미 같은 값인 행은 변경으로 잡히지 않는다.
4. `변경만`을 켜서 바뀐 행을 확인하고 아니다 싶은 행은 되돌린다.
5. `저장`을 누른다. 다른 문서와 같은 저장 흐름(저장 전 검사, 충돌 확인, 한 트랜잭션, 저장 로그)을 거친다.

- `REG_DT`의 `레코드를 등록한 일시`처럼 여러 테이블에 같은 설명을 넣으려면 `설명` 칸에 적고 적용한다. 테이블마다 다른 설명은 `설명` 칸을 비워 두면 그대로 남는다.
- 두 칸이 모두 비어 있으면 아무것도 바꾸지 않고 `넣을 이름이나 설명을 입력하세요.`가 보인다. 빈 값으로 여러 테이블의 값을 한꺼번에 지우는 일을 막으려고 이렇게 했다. 지우는 것은 셀에서 직접 한다.
- 이름과 설명을 합쳐 길이 한도를 넘게 되는 행은 건너뛰고 그 수를 알린다. 이름에 `§`(그 연결의 구분자)가 있으면 아무것도 바꾸지 않는다.
- 같은 컬럼을 테이블 문서에서도 열어 고친 채로 이 문서를 먼저 저장하면, 테이블 문서를 저장할 때 [저장 충돌](comments.md#26-저장-충돌) 창이 뜬다.

## 2.11 찾아 바꾸기와 설명 편집

### 찾아 바꾸기

용어를 바꿀 때(`거래처` → `고객`) 행을 하나씩 고치지 않는다.

1. 코멘트 그리드에서 오른쪽 클릭 > `찾아 바꾸기...`(Windows `Ctrl+H` / macOS `Cmd+Option+F`).
2. 창 위에 `이 그리드에 보이는 N개 행에서 바꿉니다.`가 나온다. **바꾸는 범위는 그 그리드에 지금 보이는 행이다.** 검색·필터로 숨은 행은 바꾸지 않는다.
3. 찾을 글자와 바꿀 글자를 쓰고, 대상 칸(`이름`·`설명`)을 고른 뒤 `바꾸기`. 바꿀 글자를 비우면 찾은 글자를 지운다.
4. 상태줄에 `'거래처'을(를) 바꾼 행 N개. 저장해야 DB에 반영됩니다.`가 보인다. 확인한 뒤 `저장`을 누른다.

- 영문 약어(`ID`·`Id`)를 뜻하지 않게 바꾸지 않도록 대소문자를 가린다.
- 바꾸면 이름에 `§`가 생기거나 길이 한도를 넘는 행은 바꾸지 않고 사유별로 알린다.
- 잘못 바꾼 행은 [행 되돌리기](comments.md#27-행-되돌리기)로 되돌린다.

### 설명 편집

그리드 칸은 한 줄이라 긴 설명은 보고 고치기 어렵다. 그래서 큰 창에서 여러 줄로 고친다.

1. 코멘트 그리드에서 행 **하나**를 고르고 오른쪽 클릭 > `설명 편집...`(`Shift+F2`). 여럿을 골랐으면 메뉴가 꺼져 있다.
2. 창 위에 그 행의 이름이, 아래 입력칸에 지금 설명이 들어 있다. `Enter`로 줄을 바꾼다.
3. `확인`을 누르면 그 행의 설명만 바뀐다. 이름과 합친 길이가 한도를 넘으면 `확인`이 꺼지고 지금 길이와 한도가 보인다. 한도는 연결 종류를 따른다(MariaDB는 글자 수).
4. 그리드에만 들어가 `변경`으로 표시된다. `저장`을 눌러야 DB에 반영된다.

- 여러 줄 설명은 그리드에서도 줄 수만큼 행이 높아져 보인다.
- 줄바꿈은 Windows 방식(CRLF)으로 저장하므로 같은 DB를 쓰는 기존 프로그램에서도 줄이 바뀌어 보인다.
