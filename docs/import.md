## 3.2 가져오기

1. 내보낸 파일을 엑셀에서 열어 `이름`·`설명` 칸을 고친다. `개체유형`·`스키마`·`상위개체`·`개체명`은 그대로 둔다. 이 칸으로 행을 찾아 맞추기 때문이다.
2. 같은 문서에서 **가져오기**(툴바, **문서 > 가져오기...**, 또는 트리 오른쪽 클릭 **가져오기...**)를 누르고 파일을 고른다.
3. 값이 그리드에 채워지고 바뀐 행에 `변경`이 체크되며 `변경 항목: N개`가 늘어난다. **아직 DB에는 아무것도 쓰지 않았다.**
4. 툴바의 `변경만`을 켜면 바뀐 행만 모아 볼 수 있다. 잘못 들어간 행은 오른쪽 클릭 **원래 값으로 되돌리기**로 되돌린다.
5. 확인이 끝나면 **저장**을 누른다. 저장 로그와 저장 이력에 항목마다 이전 값과 새 값이 남는다([2.5](comments-save.md#저장-로그), [2.14](comments-history.md#214-저장-이력)).

가져오지 못한 행은 이유별로 알려 준다.

| 이유 | 뜻 |
|---|---|
| 매칭 실패 | 문서에 그 개체·항목이 없다. 이름이 바뀌었거나 다른 문서에서 내보낸 파일이다 |
| `§` 포함 | 이름에 `§`가 들어 있다 |
| 길이 초과 | 이름과 설명을 합쳐 한도를 넘는다(SQL Server 7,500바이트, MariaDB·MySQL은 개체마다 글자 수, Oracle 4,000바이트, PostgreSQL은 한도 없음) |
| 같은 항목이 겹침 | 파일 안에 같은 항목의 행이 둘 이상 있다. 뒤의 행 값이 들어간다 |

- **파일의 빈 칸은 있던 값을 지우지 않는다.** 이름만 채운 행을 가져오면 설명은 그대로다. 값을 지우려면 그리드에서 직접 지운다.
- 이름만 채운 행이 기존 설명과 합쳐 길이 한도를 넘으면 그 행은 넣지 않고 길이 초과로 알린다.
- `이름`·`설명` 열 중 하나를 지운 파일을 가져오면 지운 열의 값은 건드리지 않는다. 둘 다 없으면 `파일에 '이름'·'설명' 열이 없습니다.`라며 가져오지 않는다.
- 엑셀에서 `CSV (쉼표로 분리)`로 다시 저장한 파일도 한글이 깨지지 않고 읽힌다. 인코딩을 알아서 판별한다.
- 여러 줄 설명의 줄바꿈은 앱의 줄바꿈(CRLF)으로 맞춘다. 내보낸 파일을 손대지 않고 가져오면 줄바꿈만 다른 값은 바뀐 것으로 보지 않는다.
- 끝 칸이 빠진 CSV 행은 그 칸을 빈 칸으로 읽는다.
- 어떤 인코딩으로도 읽을 수 없는 파일은 가져오지 않고 이유를 알려 준다. 그리드는 그대로다.
- 지금 문서에 읽어 온 항목에만 채운다. 다른 문서에서 내보낸 행은 매칭 실패로 나온다. 예를 들어 테이블 문서에서는 그 테이블의 행만 들어간다.
- `미작성만`·검색으로 걸러 둔 상태여도 숨은 행까지 맞춰 채운다.
- 파일을 읽어 곧바로 DB에 쓰는 길은 없다. 늘 그리드에서 확인한 뒤 **저장**을 눌러야 반영된다.
