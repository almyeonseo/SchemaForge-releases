# 6. 문제 해결

[목차](README.md) · 이전: [5. 설정과 단축키](settings-shortcuts.md)

## 6.1 자주 겪는 문제

**그리드 칸을 골랐는데 타이핑이 안 된다.**
칸을 고른 것만으로는 입력이 시작되지 않는다. 같은 칸을 한 번 더 클릭하거나 `F2`를 누른다.

**`Ctrl+N`(macOS `Cmd+N`, 새 쿼리)을 눌러도 아무 일이 없다.**
DB 탐색기에서 연결이나 그 아래 노드(DB·폴더·개체)를 먼저 골라야 한다. 상태바에 안내가 뜬다. `Ctrl+O`(macOS `Cmd+O`), 정의서 내보내기도 같다.
새 쿼리는 고른 노드의 DB에 붙는다(연결을 골랐으면 기본 DB).

**`F5`를 눌렀더니 쿼리가 아니라 트리가 새로고쳐졌다.**
포커스가 DB 탐색기에 있었다. 편집기를 한 번 클릭한 뒤 누르거나 `Ctrl+Enter`(macOS `Cmd+Enter`)를 쓴다.

**저장을 눌렀는데 저장되지 않았다.**
문서 아래 상태 문구를 본다. 한글명에 `§`가 있거나, 한글명과 설명이 너무 길면(합쳐 7,500바이트 초과)
저장을 시작하지 않는다. 문제 항목을 고친 뒤 다시 저장한다. 하나라도 걸리면 그 문서의 어떤 항목도 저장되지 않는다.

**`저장 충돌을 확인할 수 없어 저장하지 않았습니다`가 뜬다.**
저장 직전에 서버 값을 다시 읽지 못했다. 연결 상태를 확인한 뒤 다시 저장한다. 편집한 값은 남아 있다.

**연결 테스트가 인증서 오류로 실패한다.**
서버가 자체 서명 인증서를 쓰고 있다. 연결 대화상자에서 **서버 인증서 신뢰**를 켠다.

**MariaDB 연결 테스트가 TLS 오류로 실패한다.**
MariaDB 연결은 늘 암호화한다. 서버에 TLS가 켜져 있지 않으면 붙지 못하니 DB 관리자에게 TLS 설정을 요청한다. 서버가 자체 서명
인증서를 쓰면 **서버 인증서 신뢰**를 켠다.

**MariaDB 연결에서 저장 프로시저·함수 폴더가 비어 있다.**
계정에 그 DB의 `EXECUTE` 권한이 없다. MariaDB는 `SELECT`만 있는 계정에 루틴을 보여 주지 않는다. DB 관리자에게 `EXECUTE` 권한을 요청한다.

**MariaDB에서 저장하다 중간에 멈췄다.**
MariaDB는 한 건씩 바로 반영되어 앞의 항목은 이미 저장되어 있다. 상태 문구(마우스를 올리면 전문)와 출력 창에서 실패한 항목과 사유를 보고
고친 뒤 다시 **저장**하면 남은 항목만 저장한다([1.5](getting-started.md#mariadb-저장)).

**트리 폴더에 `불러오기 실패: …`가 뜬다.**
출력 창의 `[오류]` 줄에 원인이 있고 자세한 내용은 오류 로그에 남는다(아래 6.4). 폴더를 오른쪽 클릭해 **새로고침**으로 다시 읽는다.

**연결을 펼쳤는데 기본 DB 하나만 보인다.**
DB 목록을 읽지 못한 것이다. 앱은 기본 DB로 목록을 묻고, 기본 DB에 붙지 못하면(오프라인, 복원 중, 권한 없음) `master`로 다시 묻는다.
둘 다 실패하면 기본 DB만 남기고 출력 창에 이유를 적는다. 계정에 다른 DB 접근 권한이 있는지 확인한 뒤 연결을 오른쪽 클릭해 **새로고침**한다.

**방금 만든 DB가 트리에 없다.**
DB 목록은 연결을 처음 펼칠 때 한 번 읽는다. 연결을 오른쪽 클릭해 **새로고침**한다. DB 노드의 **새로고침**은 그 DB의 폴더만 다시 읽어 DB 목록은 바뀌지 않는다.

**기본 DB가 아닌 DB를 열었는데 연결 대화상자에서 DB를 바꿔야 하나?**
아니다. 연결 하나로 같은 서버의 접근 가능한 DB를 모두 본다. 연결을 펼쳐 그 DB 노드 아래에서 열면 그 DB에서 읽고 그 DB에 저장한다.
**운영 DB도 같은 트리에 함께 보일 수 있으므로** 저장 전에 탭 도구 설명이나 출력 창의 DB 이름을 확인할 것.

**검색했는데 있는 개체가 나오지 않는다.**
검색은 검색 패널 맨 위 콤보에서 고른 DB 하나만 본다. 콤보의 범위를 확인한다. 패널을 연 뒤 트리에서 다른 DB를 눌러도 범위는 따라가지 않는다.
컬럼을 찾으려면 `개체`가 아니라 `컬럼`을 고른다([1.4](getting-started.md#검색)).

**컬럼 검색 결과를 더블클릭했는데 문서에서 그 컬럼이 골라지지 않았다.**
그 문서에 검색어나 `미작성만`이 걸려 있어 행이 가려진 경우다. 앱은 필터를 대신 풀지 않고 문서 아래 상태 문구로 알린다. 필터를 풀고 다시 연다.

**`상위 1000개 행 선택`을 눌렀는데 결과가 없다.**
조회문을 새 탭에 채우기만 하고 실행하지 않는다. `F5`나 `Ctrl+Enter`(macOS `Cmd+Enter`)로 실행한다.

**붙여넣었는데 일부 행이나 칸이 들어가지 않았다.**
상태 문구에 사유가 적힌다. 붙여넣기는 다음을 넣지 않는다.

| 넣지 않는 것 | 이유 |
|---|---|
| 빈 셀 | 지금 값을 지우지 않는다. 지우려면 셀에서 직접 지운다 |
| 한글명에 `§`가 든 줄, 한글명과 설명을 합쳐 7,500바이트를 넘는 줄 | 저장할 수 없는 값이다 |
| 셋째 칸부터 | 넣을 칸은 한글명·설명 둘뿐이다 |
| 아래 행이 모자라 남은 줄 | `N줄 중 M줄만 넣었습니다`로 알린다 |

검색·필터로 숨은 행은 건너뛰고 화면에 보이는 순서대로 넣는다. 셀을 편집하는 중에 누른 `Ctrl+V`(macOS `Cmd+V`)는 그 칸에 글자를 넣을 뿐이다.

**저장 충돌에서 내 값으로 덮어썼다. 덮인 다른 사람의 값은 어디서 보나?**
저장 로그(출력 창)와 저장 이력의 **이전 값**에 덮인 서버 값이 남는다. 되돌려야 하면 저장 이력에서 그 항목의 이전 값을 복사해 붙여넣고 저장한다([2장](comments.md)).

**저장 이력에 동료가 바꾼 내용이 없다.**
저장 이력은 이 PC에서 이 앱으로 저장한 것만 남는다. 다른 PC, SSMS, 다른 도구로 바꾼 것은 없다. 1년이 지난 이력은 지워진다.

**`[경고] 저장 이력을 남기지 못했습니다`가 출력 창에 뜬다.**
DB 저장은 이미 성공했다. 이 PC의 이력 기록만 실패했다. 이번 저장의 이전 값은 출력 창의 저장 로그에서 확인한다(앱을 끄면 사라진다).

**`GO 5`가 들어 있다며 실행되지 않는다.**
`GO` 뒤의 반복 횟수는 지원하지 않는다. 숫자를 지우고 실행한다. `GO`만 있는 줄은 그대로 쓸 수 있다([4.2](sql-editor.md#42-실행하기)).

**`ALTER DATABASE`·`BACKUP` 같은 문장이 실패한다.**
트랜잭션 안에서 쓸 수 없는 문장이다. 이 편집기는 실행 전체를 트랜잭션으로 감싸므로 실행할 수 없다. SSMS 같은 도구를 쓴다.

**예상 규모 줄이 늘 `알 수 없습니다`이거나 `조사를 멈췄습니다`라고 나온다.**
DB 접근 게이트웨이(중계 프로그램)를 거치는 연결은 실행 계획 조사를 받지 않는 경우가 있다. 앱은 한 번 실패하면 앱을 끌 때까지
그 연결에 다시 묻지 않는다. 실행에는 영향이 없다. 실행이 실패했을 때 되돌려졌는지 가릴 수 없으면 오류 문구가 그렇다고 알려 준다.

**SQL 결과가 중간에서 끊긴다.**
설정에서 행 상한을 걸어 둔 것이다(기본은 무제한). 표 아래에 `· 더 있음`이 붙어 있으면 잘린 것이다. 조건을 좁히거나 설정에서 상한을 올린다.

**큰 테이블을 조회했더니 앱이 멈춘 것 같다.**
기본은 모든 행을 받는다. **중단**(`Ctrl+.`, macOS `Cmd+.`)으로 멈추고, `TOP`이나 조건으로 좁히거나 설정에서 행 상한을 건다.

**엑셀에서 고친 CSV를 가져오면 한글이 깨질까?**
깨지지 않는다. 인코딩을 알아서 판별한다. 그래도 읽을 수 없는 파일이면 가져오지 않고 이유를 알려 준다.

**macOS에서 앱이 열리지 않는다.**
시스템 설정 > 개인정보 보호 및 보안에서 **그래도 열기**를 누른다. zip을 받았다면 터미널 `unzip`이 아니라 Finder에서 풀어야 한다.

## 6.2 업데이트

앱을 켤 때 새 버전이 있는지 확인하고, 있으면 상태바에 링크가 나타난다. **도움말 > 업데이트 확인**으로
직접 확인할 수도 있다. 켤 때 확인하지 않으려면 설정에서 끈다([5장](settings-shortcuts.md)). 자동으로 내려받지는 않으므로 링크에서 새 파일을 받아 설치한다.

Windows 설치판은 새 setup.exe를 실행하면 덮어 설치된다. 연결 프로필과 저장된 비밀번호는 그대로 남는다.

## 6.3 데이터 저장 위치

연결 프로필(연결 순서 포함), 설정, 정의서 표제부, 최근 쿼리 파일 목록, 저장 이력은 아래 폴더의 `SchemaForge.db` 한 파일에 있다.

| OS | 폴더 |
|---|---|
| Windows | 사용자 AppData(Roaming) 폴더 아래 `SchemaForge` |
| macOS | `~/Library/Application Support/SchemaForge` (Finder에서 `Cmd+Shift+G`로 이 경로를 넣는다) |
| Linux | `~/.config/SchemaForge` |

비밀번호는 AES-256-GCM으로 암호화하고 키는 설치마다 무작위로 만들어 DB 파일 옆에 둔다. DB 파일만
실수로 새어 나갔을 때 비밀번호가 그대로 보이지 않게 하는 수준이다. 이 PC의 파일에 접근할 수 있는 사람은
키 파일과 함께 풀 수 있다. OS 보안 저장소(Keychain 등)를 쓰지는 않는다.

저장 이력도 이 파일에 있으므로 이 파일을 지우거나 다른 PC로 옮기지 않으면 이력은 그 PC에만 남는다. 1년이 지난 이력은 기록할 때 지워진다.

## 6.4 오류 로그

예상하지 못한 오류는 위 폴더의 `logs/error.log`에 남는다. **도움말 > 오류 로그 폴더 열기**로 바로 연다.
연결 문자열의 비밀번호는 지운 뒤 기록한다.

화면 쪽에서 오류가 나면 앱은 꺼지지 않고 `계속 / 종료`를 묻는다. **계속**을 골라 저장하지 않은 편집을 먼저 저장할 것.

## 6.5 지원하지 않는 것

- MS SQL Server·MariaDB 이외의 DBMS
- MariaDB 컬럼·인덱스 코멘트 저장(읽기만 한다), MariaDB 연결의 SQL 편집기·정의서 내보내기·다른 DB와 비교
- 테이블·컬럼 자체를 만들거나 바꾸는 일 (확장 속성만 다룬다)
- 다른 사람의 편집을 막는 잠금 (저장할 때 충돌을 알려 주는 데까지만)
- 여러 사람의 변경 이력을 함께 보기. 저장 이력은 이 PC에서 이 앱으로 저장한 것만 남는다
- 저장 이력 화면에서 곧바로 DB 값을 되돌리기. 이전 값을 복사해 코멘트 문서에 붙여넣고 저장한다
- 여러 DB를 한 번에 검색하기
- 한글명에 `§` 넣기

- 오류가 났다면 `logs/error.log`
